# 行程和地点推荐

根据用户的目的地、日期、可用时间和目标鸟种，整理能实际使用的观鸟建议。已有信息直接使用；影响路线的关键信息缺失时再询问，仍可先查询不受影响的地点和鸟种。相对日期按用户时区换成 `YYYY-MM-DD`。

## 查询实际依据

按需要批量读取 `location_search`、`hotspots_nearby`、`species_predict`、`hotspots_target_destinations` 和鸟种查询的 schema，同一会话复用。

- 只有地名时，登录后用 `location_search` 查询，无需申请地图 Key。同名或多个合理候选时请用户选择。天地图默认搜索范围为中国大陆，境外或搜索失败时使用用户提供或其他可用工具查到的坐标，不猜经纬度。
- 用 `hotspots_nearby` 查询附近地点，用 `species_predict` 获取指定日期的鸟种预测。预测像网页一样保存当前用户的最近查询。
- 用户有目标鸟种时，先用 `species_catalog` 解析 `taxon_id`，再用 `hotspots_target_destinations` 推荐地点。参数 `taxon_id` 是整数数组，例如 `{"target_date":"2026-10-16","lat":25.04,"lon":102.71,"taxon_id":[42,73]}`（仅示意，日期、坐标和 ID 替换为实际查询信息）；CLI 自动发送重复的查询参数。写入清单用的 `taxon_ids` 是另一个参数，以各工具 schema 为准。
- 用热点鸟种、目标覆盖、距离、最近记录日期和历史季节记录筛选地点，再按需要补充少量百科特征。不要为所有候选逐一读取百科后才给路线。

## 整理路线

在聊天中直接给出建议顺序、各地点停留重点、目标鸟种、优先级及依据，区分近期记录和季节预测。工具返回的最近记录日期和目标覆盖情况应出现在推荐理由中，不能只放在导出文件里。车程没有实时导航依据时标为估算，不保证能看到目标鸟种。

开放时间、预约、交通限制等外部信息优先核对官方来源。工具不可用或换一个可靠来源仍无法核实，就停止反复查询，标明未核实并给出核实入口；不能因此拖延已有路线建议。

普通观鸟问答不需要创建开发用的 `task_plan.md`、`findings.md` 或 `progress.md`。用户需要文件时再生成清单、CSV、地图或行程文档作为补充，保留直接可读的主要建议；不覆盖已有用户文件。用户提出保存到 Bulbul 或创建练习时，按主 skill 的授权和恢复规则执行。
